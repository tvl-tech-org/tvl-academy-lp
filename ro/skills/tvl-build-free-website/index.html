Skill pentru site gratuit

tvl-build-free-website duce un site de la brief la un URL live, gratuit. Construiește un site static, îl publică pe GitHub Pages și verifică efectiv că pagina live returnează HTTP 200, cu titlul, stilurile și navigația corecte — tot ciclul, nu doar build-ul.

Fluxul Instalează skill-ul
Ce construiește

Site-uri statice care rulează pe GitHub Pages

Orice se poate servi ca fișiere simple. Dacă are nevoie de server, e în afara scopului, intenționat.

Site de o pagină

O pagină compactă de companie, serviciu, eveniment sau campanie, cu ofertă clară, dovezi și cale de contact.

Portofoliu & landing

Un profil profesional cu proiecte, studii de caz, semnale de credibilitate și linkuri de contact.

Site de documentație

Un site public de proiect sau resurse cu quick start, ghiduri, exemple și referințe.

Pagini de proiect

O casă pentru un proiect open-source sau produs — overview, status și linkuri.

Hub-uri de resurse

Un index curat de linkuri, descărcări și referințe pe un singur subiect.

Aplicații ușoare

Unelte și demo-uri doar client-side, care rulează integral în browser.

Cum funcționează

Fluxul în zece pași

De la citirea conținutului până la un URL live verificat — fiecare pas e explicit și nu se oprește la „am dat push pe GitHub".

1

Evaluarea conținutului

Examinează fișierele, URL-urile și starea curentă a repository-ului.

2

Identificarea constrângerilor

Clasifică tipul de site, modelul de deploy (root, /docs, Actions) și proprietatea (user vs organizație).

3

Încărcarea referințelor

Consultă rubrica GitHub Pages și blueprint-urile de site.

4

Alegerea blueprint-ului

Alege template-ul potrivit pentru un site nou sau redesignat.

5

Build

HTML/CSS/JS simplu sau un generator static existent — fără dependențe de backend.

6

Configurarea deploy-ului

Alege branch deploy sau GitHub Actions; adaugă .nojekyll când e nevoie.

7

Verificare locală

Servește local și verifică statusul HTTP și randarea conținutului înainte de publicare.

8

Publicare

Creează sau refolosește repository-ul, dă push pe main și configurează GitHub Pages.

9

Verificarea URL-ului live

Confirmă HTTP 200, titlul/H1, încărcarea asset-urilor și navigația pe URL-ul publicat.

10

Închidere

Livrează URL-ul final, linkul de repo, metoda de deploy, rezultatele testelor și limitele.

Deploy

Moduri GitHub Pages

Skill-ul alege modelul de deploy potrivit repository-ului, apoi îl configurează.

Branch · main root

Servește site-ul direct din root-ul branch-ului main. Cel mai simplu pentru site-uri scrise de mână.

Branch · /docs

Servește din subdirectorul /docs al main, ținând sursa și site-ul unul lângă altul.

GitHub Actions

Un workflow construiește output-ul static și publică artefactul — pentru generatoare statice.

.nojekyll

Când asset-urile statice trebuie să ocolească procesarea Jekyll (de exemplu foldere care încep cu underscore), skill-ul adaugă un fișier .nojekyll, ca fișierele să fie servite ca atare.

Verificările

Nimic nu pleacă neverificat

Două porți: tot ce trebuie să fie adevărat înainte de publicare și tot ce e confirmat pe URL-ul live după.

Înainte de publicare

  • Conținut static doar — HTML, CSS, JS, imagini, asset-uri generate.
  • index.html există la root-ul de publicare.
  • Căile către asset-uri merg de pe URL-ul publicat, inclusiv pe subcale de proiect.
  • Fără linkuri de navigație locală rupte.
  • Titlu, H1, meta description și tag-uri de social preview cu sens.
  • Accesibilitate: landmarks, labels, alt text, navigație cu tastatura, focus, contrast.
  • Responsive pe mobil și desktop; dimensiuni de asset optimizate.
  • Fără secrete, tokeni, chei sau căi locale comise.

Verificarea URL-ului live

  • URL-ul returnează HTTP 200.
  • Titlul și H1 așteptate sunt vizibile.
  • Stilizarea CSS se încarcă corect.
  • Imaginile se randează corect.
  • Navigația internă funcționează.
  • URL-ul corespunde modului de deploy GitHub Pages ales.
Output

Ce livrează

Pentru o cerere de build-and-publish, o închidere fixă — pentru cereri doar de planificare, un plan concis și numele blueprint-ului.

LIVE SITE: <url> REPOSITORY: <url> WHAT CHANGED: [listă cu buline] DEPLOYMENT: modul GitHub Pages și sursa VERIFICATION: rezultate local, Actions/Pages, URL live LIMITS: constrângerile aplicabile
Scop

Ce nu face

GitHub Pages e un host static. Skill-ul refuză, intenționat, orice are nevoie de server.

Fără backend

Fără baze de date, cod server-side, joburi programate sau API-uri private.

Fără secrete

Fără secrete de runtime, autentificare sau configurare dependentă de mediu.

Fără date dinamice

Fără procesare de plăți, stocare de date private sau sisteme cu conținut trimis de utilizatori.

Limite de serviciu

GitHub Pages impune limite de dimensiune, bandă și timp de build. Skill-ul le declară la închidere, ca să nu apară surprize mai târziu.
